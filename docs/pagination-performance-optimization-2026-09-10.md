# 分页性能优化实测（2026-09-10）

## 结果

5,000段正文与500个对象、同一套三轮配对测试：完整分页每次输入的分页重算均耗时中位数从155.89ms降至48.82ms（下降68.7%）；稀疏分页从104.80ms降至10.36ms（下降90.1%）。稀疏分页输入帧间隔P95约16.8ms，三轮均无超过50ms的长任务；完整分页仍存在长任务。

## 优化内容

行内分页应用器为每个正文块反复扫描全部页和 slot，普通不跨页段落也执行扫描。修改为每轮发布只建立一次片段索引，按块 ID 查询是否有片段及其续页位置。索引不跨轮缓存，不产生新的模型状态。

生产改动仅在 `inline-break-applier.ts`。保持页首续片段判断、文字锚点匹配、页间遮罩计算、缺少锚点时的失败回退、表格排除规则，以及事务回滚、冻结和挂载生命周期。自由拖动行为保持上轮修正版。

## 证据与验证

- 方法级剖析中，五千段完整分页每次输入约190ms，其中 InlineBreakApplier.apply 约121ms；稀疏分页约125ms，其中该方法约103ms。细粒度探针有开销，这些数字只用于定位热点。
- 确定性复杂度回归：1,024 块、64 页，旧实现读取 page.slots 129,536 次，候选64次。旧实现不满足新测试上限，候选满足；测试不依赖墙钟或机器性能。
- 新增3项回归覆盖线性扫描、非页首残留片段及表格排除、多块续页分别映射和清理旧状态。
- 415项单测通过；12项Chrome页面回归通过，包括自由拖动/缩放/撤销/取消、图片Caption、远端事务、超长表格单元格分页和表格全屏编辑。
- 编辑器 production 构建通过；未改包版本、未提交或发布。

优化后独立剖析中，InlineBreakApplier.apply 单次输入均耗时为完整分页约0.13ms、稀疏分页约0.08ms；完整分页剩余热点是全文自然高度测量和布局核对。该剖析在正式采样结束后执行，探针成本不混入下面的三轮对比。

## 对比方法

- 对照版本是上轮恢复自由拖动后的源码，候选在此基础上加入本次优化。不是最初的Git HEAD。两者源于 `db4c8fc5c10d71c707d3e8f9b8f55cc6186cab8f`，使用相同已安装依赖和独立源码目录。
- Chrome 152.0.7977.83，macOS 26.5，Intel i7-13700K，64GiB RAM，1440×1000；Angular development Playground，无CPU限速。
- 正文虚拟化开启、空闲预热关闭；完整分页沿用全文挂载，稀疏分页验证选项实际生效。
- 三轮、交替版本顺序，100/1,000/5,000段固定中文正文分别搭配10/100/500个矩形；操作与上轮基准一致。
- 真实键盘输入36字符，断言模型长度；60帧滚动断言真实滚动，60帧拖动断言坐标提交；另含20次横移和10次视图缩放。
- 正式对比保留相同轻量探针，不启用上述逐方法剖析；本任务的构建和功能回归已结束后才采样。未独占工作站。
- 表格为各轮单次分页重算均耗时的中位数、各轮rAF帧间隔P95的中位数、每轮Long Task数量的中位数。Long Task指超过50ms。

## 适用范围与剩余问题

- 本次解决已证实的重复扫描瓶颈。完整分页仍需全文DOM测量，改善不等于所有大文档操作达到60fps。
- 合成样本为文字和矩形，不代表大表格、真实媒体解码、复杂组合、移动设备或Tauri WebView。
- 开发构建的耗时不可直接视为生产包性能；功能构建与性能测量是两种不同证据。
- 初始化统计包含固定等待，heap为浏览器近似诊断值，均不用于启动耗时或内存泄漏结论。
- 已记录 36 次场景运行，异常 0 次。
