# 绝对定位范围修复：性能对比（2026-09-10）

## 结论与边界

恢复自由拖动后的候选与修改前 HEAD 对比，54 个场景运行全部完成，异常为零。

- 100/1,000 段场景下，输入帧间隔 P95 的三轮中位数约 16.7–16.8ms，长任务中位数为零；本次改动未增加输入、横移提交和缩放的分页重算次数。
- 5,000 段 / 500 对象时，流式布局各操作帧间隔 P95 中位数仍约 16.7–16.8ms。
- 同一规模下，完整分页的每次输入分页重算均耗时，三轮中位数为基线 162.31ms、候选 164.63ms（+1.4%）；稀疏分页为 112.09ms、118.64ms（+5.8%）。两种分页模式每轮36次输入都出现约36个长任务，属于明显瓶颈。
- 完整分页候选各轮均耗时为201.74/164.63/155.33ms，基线为165.09/162.31/155.41ms；稀疏分页同样有轮次波动。这些样本足以发现大文档卡顿，但不足以证明1%–6%的差异具有统计显著性，也不能宣称零性能回归。
- 拖动中没有逐帧分页重算；松手仍触发一次重算，大文档会停顿。拖动 P95 容易掩盖这一孤立长任务，不能代替松手延迟。
- 后续应优先剖析分页重算并推动增量更新；本次没有扩大到分页引擎重构。

以下时间是浏览器开发构建的相对结果，不能直接当作生产包、Tauri WebView 或移动设备的耗时。

## 测试环境与方法

- Intel Core i7-13700K，64 GiB RAM，macOS 26.5，Chrome 152.0.7977.83，1440×1000，无 CPU 限速。
- 基线：BlockCraft `db4c8fc5c10d71c707d3e8f9b8f55cc6186cab8f`；候选：同一提交加本次范围修复，已移除内容区/纸张拖动约束。
- 使用同一套已安装依赖、独立源码目录和浏览器上下文，Angular development Playground；未连接协作服务器或业务数据。
- 所有场景启用正文虚拟化，关闭空闲预热。完整分页按既有机制挂载全文；稀疏分页确认 controller.options.sparseView=true。
- 100/1,000/5,000 段固定中文正文，分别搭配 10/100/500 个 100×60 图形。根级绝对定位层作为原子子树，全部对象随该层挂载。
- 每组独立运行三轮，第二轮交换版本顺序；表格取三轮中位数。测试期间不运行本任务的其他构建或功能回归，但未独占整台工作站。
- 滚动：60 帧往返约2,400px，断言实际滚动超过500px；输入：真实键盘输入36字符，间隔35ms，断言模型长度增加36。
- 拖动：调用生产 startDrag 后发送60帧 pointermove 和 pointerup，断言坐标变化；提交：20次横移；缩放：75%/100%切换10次。
- 记录 rAF 帧间隔、>50ms Long Task、分页重算/测量的次数与同步耗时。beforeinput 到下次 rAF 的时间仅供诊断，不等于绘制完成延迟。
- 方法包装计时有少量探针成本；嵌套方法耗时不可相加。surfaceRefresh 次数包含缓存命中，不等于索引重建次数。
- 初始化数字包含固定约1,200ms等待，不用于启动性能结论；performance.memory 是近似诊断值，不作内存泄漏结论。
