# 文本对象内容自适应性能优化验证（2026-10-12）

第一阶段调整 `TextContentAutoFit` 内部调度与挂载生命周期，后续改为固定浮动对象逐个虚拟化、自适应浮动对象常驻。CSS 继续计算自然内容尺寸，JS 读取并缓存结果供对象几何和虚拟渲染使用。原有尺寸模式、创建手势、数据格式、撤销和对象组合语义不变；没有修改版本号。下文批量测量计时来自第一阶段冻结构建，不代表后续浮动修复重新完成了同一轮压测。

## 改动与影响范围

- 旧版每个对象分别写临时样式、同步读取、恢复样式并提交模型，批量变化会反复触发布局和根块估高。
- 新版在同一文档、同一帧内先读取所有待测对象的原始状态，再统一准备自然尺寸样式、统一测量、统一恢复，最后合并为一次不进入撤销历史的事务。尺寸不变不写回。
- 虚拟卸载和拖拽暂停时断开观察、移除待测任务；重新挂载和恢复时重新观察与测量。文档之间互不合并。
- 修改前核对了文本框/艺术字调用方、组件卸载与重新挂载、对象几何写回、对象组合边界和根虚拟化事件路径。保持 `placement.updateObjectGeometry` 作为几何写入入口。
- 仍保留同步自然尺寸读取，未把现有固定外框/绝对定位内容改为永久 `height:auto`，避免改变形状内缩、裁切、最小/最大尺寸和对齐语义。未改动对象组合协调器的逐成员重排。

## 方法和样本

- 优化前为提交 `638f2a6c` 的 helper；优化后为本次工作区 helper。两个版本分别冻结源码并生成 Angular development 静态构建，关闭源码映射和构建 watcher。其余受检源码相同，测量脚本与插桩相同。
- 每个“版本 × 浏览器 × 场景 × 固定/自适应”组合预热 1 轮、有效测量 2 轮，版本和浏览器顺序运行；每轮交替固定/自适应。共 48 个样本，其中 32 个有效样本、16 个预热样本，无失败。
- 下表为各有效轮次阶段指标的中位数。帧指标来自 RAF 回调间隔，包含调度延迟；两轮样本不足以推断线上分布，也不是硬件 FPS。
- `nested-100`：一个 `render-unit` 包含 100 个文本对象（文本框/艺术字各半），后跟 200 段正文。连续改宽阶段将已挂载对象宽度在 220/320 px 间切换 12 次，触发横排文本的高度自适应。这个容器不是 `object-group`。

## 向上滚动渲染校验（追加）

此前的功能回归覆盖“滚到下方、离屏修改、再跳回上方”，性能脚本也包含上下往返，但没有逐屏向上滚动时逐对象核对尺寸。本次新增 `e2e/text-fit-upward-scroll.spec.ts` 补齐这个边界。

虚拟渲染按根块的累计高度查找视口及上下缓冲区。已测量对象使用尺寸缓存；未测量对象先使用模型估算占位。挂载后 CSS 产生真实尺寸，自适应缓存和虚拟高度表随之更新，再补偿可见内容的滚动锚点。容器的嵌套子树随根容器整体挂载。因此首次未测量时的位置是估算值，不要求对象有固定高度。

- 每例 220 个根块，8 个分散排列的自适应文本对象；一半由短变长，一半由长变短，同时修改字号、内边距及约束宽度/高度。
- 先滚到最下方，确认全部目标已卸载，再离屏修改；6 个对象带旧尺寸缓存，另 2 个从未渲染且没有 `textFit` 缓存。
- 第一遍以每步 180px 连续向上滚动，核对可见段落的锚点补偿；第二遍再次离屏修改为原内容，使用原生向上滚轮回到顶部。每遍均确认全部 8 个对象实际经过视口。
- 覆盖横排文本框、竖排文本框宽度自适应、横排艺术字，以及保留视图重新挂载和销毁后重建两条路径。独立的非虚拟文档提供完整渲染的参考尺寸。
- 每次挂载后同时检查 DOM 内容、实际宽高、`textFit`、虚拟高度、内容溢出、相邻段落重叠和稀疏挂载数量。

Chromium、Firefox、WebKit 各 6 项，共 **18 项全部通过**，无重试或跳过。每遍 42–46 次滚动操作（诊断中的 `steps` 为从零起算的循环索引 41–45）；本轮参考尺寸最大差值 **0px**，792 次可见锚点检查最大偏移 **0px**。检查了横排/竖排回顶截图，未发现文字裁切或与后文重叠。这里只证明所列场景，未覆盖 CSES/Tauri、分页模式或所有嵌套容器组合。

本次只补测试和验证记录，没有进一步修改生产算法。运行方式：


## 浮动对象向上进入视口（历史验证，方案已替换）

以下是此前保守范围方案的历史记录；最终实现已移除该方案，验证结果不能代表当前逐对象挂载实现。

### 复现与职责

正文流的累计高度表不能直接解决浮动对象。`placement-layout` 是零高度的绝对定位层，
索引原先依据原始高度/旧 `textFit` 判断是否挂载。当对象位于 y=3000，长文本框实际应
延伸到 y=5000，但初始高度只有 180 时，从下方跳到 y=4400 会持续漏挂载。
修改前 Chromium 专项已复现，日志为 `/tmp/bc-fit-floating-before.log`。

- Object 负责自然尺寸批量测量，并在事务完成后记录本次文档实例的有效测量；结果与原尺寸相同也确认有效。
- Placement Surface 负责内容/属性/结构/宽度/排版指标/字体变化后的失效。移动和旋转不使内容尺寸失效；有效记录跨卸载保留、随文档销毁清理。
- Virtualization 将“待测量候选范围”和“文档实际范围”分开。未测量或失效对象按现有自适应轴上下限建立旋转感知的候选范围，测量后收紧；候选范围不增加文档高度或页数。
- 挂载对象在容器宽度/排版指标变化时也请求一次批量测量，防止固定 inline 尺寸未变、ResizeObserver 无通知导致缓存持续失效。该边界先通过测试复现再修复，日志为 `/tmp/bc-fit-floating-width-before.log`。
- 包围范围使用有效 `textFit`，修正已缩小对象仍被原始 height 撑大，以及旋转竖排对象遗漏拟合宽度的问题。缓存只存在包内 WeakMap，不增加快照字段或宿主 API。

## 最终方案：固定浮动对象逐个虚拟化，自适应浮动对象常驻

用户确认采用按尺寸模式划分的策略。设计见 `floating-object-virtualization-design-2026-10-12.md`。

- 根级浮动层的固定对象按坐标/包围盒逐个挂载，包含旋转与有效 `textFit`；自适应文本对象从初始化起常驻，含自适应成员的组合整体常驻。普通流式容器内部仍原子挂载。
- 索引保存固定对象区间树和常驻 ID；滚动不扫描模型内容、不读取对象 DOM。移除前一方案的测量有效性 WeakMap 与保守范围，保留 CSS 批量测量及派生尺寸写回。
- DocVM/CRUD 使用浮动层稀疏子视图，模型顺序与跨父级所有权仍由同一事务同步。固定对象离屏释放组件，未新增第二层离屏缓存。选区、导航、keep-alive/交互租约及全量导出按原有能力显式挂载目标。
- IME 期间同父重排延后；一个对象租约释放时，即使同层还有其他租约，也重新收敛子窗口。文档底边由实际范围决定，常驻策略不扩大分页页数。

最终源码定向单测 **375/375 通过**；`pnpm build:editor` 与全部随构建门禁通过。
浮动专项在 Chromium/Firefox/WebKit 各 7 项，共 **21/21 通过**：初始常驻、固定兄弟不创建、
上下滚动、离屏内容/属性变化、模式切换、多个对象租约、全量租约、DOM 顺序、组合与撤销重做、
