# PRD：BlockCraft 修订模式 v1

## 1. 概述

为 BlockCraft 增加类似 Word、Google Docs 的修订模式。编辑动作以可审阅的修订记录保存，宿主可以展示、接受、拒绝或重新裁决；Yjs 负责数据合并，编辑器不负责账号、角色或服务端权限。

第一版覆盖文字和同父级流式结构，并保证多人离线后相反审批或不可交换结构修改不会被静默覆盖。

## 2. 目标

- 修订模式下保留文字插入、删除、替换和段落边界变化的原始数据。
- 支持任意整块新增/删除，并在标记视图中明确展示。
- 所有副本以任意顺序、重复合并 Yjs 更新后得到同一修订与冲突状态。
- 接受/拒绝立即改变视图投影，但只在宿主检查点物化底层正文。
- 提供可嵌入的评审面板、只读最终态和完整文档快照。

## 3. 用户故事

### US-001：开启修订模式

**描述：** 作为文档作者，我希望开启修订模式，让后续编辑成为可审阅建议。

**验收标准：**

- [ ] 宿主提供有效 `actorId` 后可切换 `off` / `track`。
- [ ] 缺少有效身份时开启修订模式抛出明确错误。
- [ ] 编辑器不包含角色或权限判定。
- [ ] 类型检查和 editor 构建通过。

### US-002：记录文字与段落结构修订

**描述：** 作为作者，我希望键入、删除、替换、IME、粘贴和段落拆分/合并都成为修订。

**验收标准：**

- [ ] 插入内容保留在 Y.Text，并通过独立修订范围标注。
- [ ] 删除内容在检查点前不从 Y.Text 移除。
- [ ] 跨块删除按一次输入动作分组。
- [ ] Enter 和段首 Backspace 分别产生边界新增、边界删除修订。
- [ ] 同一作者连续相邻编辑归并到同一评审组。
- [ ] IME 一次 composition 只产生一个逻辑修订组。

### US-003：评审与离线冲突

**描述：** 作为评审者，我希望接受、拒绝或重新裁决修订，并在离线相反操作时看到冲突。

**验收标准：**

- [ ] 决策记录 append-only，并保存操作者身份快照和 `supersedes`。
- [ ] 同一修订同时存在接受、拒绝活动头时状态为冲突。
- [ ] 重新裁决覆盖当前全部活动头；迟到决策可重新打开冲突。
- [ ] 可交换的跨作者行内修改自动堆叠。
- [ ] 不可交换的块/边界重叠形成结构冲突组。
- [ ] Ctrl/Cmd+Z 不删除审批历史，重新裁决使用显式命令。

### US-004：标记视图、最终态和评审面板

**描述：** 作为评审者，我希望在正文标记和右侧列表中检查修订，并预览最终结果。

**验收标准：**

- [ ] 插入、删除、边界和冲突具有独立主题化视觉状态。
- [ ] 面板可筛选、定位、接受、拒绝和批量操作。
- [ ] 面板只发出操作意图，不判断业务权限。
- [ ] 最终视图为隔离、只读快照。
- [ ] 存在任何冲突时最终预览和干净导出明确失败并定位冲突。
- [ ] 使用浏览器验证标记、面板、只读和响应式布局。

### US-005：保存与检查点

**描述：** 作为宿主，我希望保存完整修订文档，并在副本已汇合后安全压缩。

**验收标准：**

- [ ] `BlockCraftDocumentSnapshot` 完整往返正文、修订、决策和 epoch。
- [ ] 宿主可基于完整快照实现自己的文件封装和迁移；editor 不修改具体宿主文件格式。
- [ ] 普通保存不物化修订。
- [ ] 检查点校验 epoch、state vector、已裁决状态和冲突。
- [ ] 成功检查点物化正文、清理修订并提升 epoch。

## 4. 功能需求

- FR-1：公开 Revision 类型、配置、查询、审批、冲突、投影和检查点 API。
- FR-2：修订记录与决策使用独立顶层 Yjs Map，正文仍为单一内容源。
- FR-3：文字目标使用相对位置；JSON 快照导出为可重建的块 ID 和绝对偏移。
- FR-4：待审/已接受新增在最终态保留，待审/已接受删除在最终态移除；拒绝反向处理。
- FR-5：作者可缩放自己的待审新增；新增范围采用紧边界，边界上的其他新增保持相邻、范围内部新增形成依赖；后续破坏性行内修订按既有相对范围边界拆段并通过依赖堆叠，保持一个评审分组。不可交换的结构重叠仍进入冲突组。
- FR-6：整块移动、表格行列和对象几何修改不生成 v1 修订，但功能保持可用并按普通 Yjs/Undo 操作执行；修订模式不是功能禁用开关。
- FR-7：UI 使用 OnPush、字体图标和 `--bc-revision-*` 主题变量。
- FR-8：修订变化只刷新受影响块和面板索引，不扫描全部已挂载 DOM。

## 5. 非目标

- 不实现账号、角色、权限、服务端更新准入或离线副本封禁。
- 不追踪粗体、颜色、链接等格式变化。
- 不追踪表格行列、单元格结构、跨容器移动和对象移动/缩放。
- 不提供 Original 视图、可编辑最终态或 DOCX 原生修订导入导出。
- 不升级到 Yjs 14 RC。

## 6. 技术约束

- 所有正文与修订突变必须位于 Yjs transaction。
- 输入必须接入现有 `InputTransformer` 和 `CompositionSession`。
- Undo 同时覆盖正文变化和修订记录，决策 Map 不进入普通 Undo scope。
- 协同位置不使用裸绝对 index 作为运行时唯一引用。
- 公开契约同步更新 ai-skills 与 `MIGRATIONS.md`，不修改 npm 包版本。

## 7. 成功指标

- 两到三个离线 Y.Doc 的更新以不同顺序、重复合并后，修订状态和最终投影一致。
- 关闭修订模式的输入路径不增加全量文档扫描或额外 DOM 查询。
- 1000 条修订记录下，单块输入只重新计算该块的修订区间。
- 无修订、带修订和带冲突的 `BlockCraftDocumentSnapshot` 均通过往返测试。

## 8. 已确认决策

- 最终态只读；冲突时阻止最终输出。
- 审批不进入普通撤销，使用显式重新裁决。
- 作者信息由宿主传入并随修订保存快照。
- 视图立即投影审批结果，底层在显式检查点后才物化。
- 行内重叠自动堆叠，破坏性结构重叠人工裁决。

## 9. 开放问题

无。v1 产品与技术边界已在实施计划中锁定。
