# 执行与验证：把设计变成当前宿主能编辑的文档

> Last updated: 2026-10-08

## 与 HTML 设计流程衔接

整体视觉任务先按视觉指南完成探索稿，视觉方向形成后补充能力标注与落地参数，再走下面的原生写入流程；局部文字/样式调整可直接执行。HTML 不增加写入权限，生成可执行参数与保存验证仍必须经过本页的合同检查。不能把“HTML 已完成”作为用户所要求的原生文档完成状态。

## 先读取，再设计局部变更

读取用户指定的范围和当前文档。文档级任务遇到 paged context 时继续读取需要的 outline 页；省略的块不等于不存在。需要精确修改的块读取完整 text.delta 和 props，避免重建全文丢失嵌套内容。

只改用户授权范围。保留事实、链接、行内材料、具名区域及已有权限；一个“调标题字号”的请求不应连带重构整页。业务具名区域即使无可见外观也有语义，不能为减少容器盲目展开。

## 编辑器内 Agent 路径

1. 读取 `blockcraft.get_capability` 中相关 skill，再按需读 block/inline 能力。目录摘要不包含完整参数合同。
2. 区分“可理解”“可创建”“可更新”三种能力。检查 createParameters、writableProps、atomicProps、insert 与父子约束。没有工具不是字段名猜得不对；不反复试探未知写入协议。
3. 新块用 create-blocks/replace-block 的 Schema 参数，由宿主生成 ID 和默认值；不返回完整 Snapshot、HTML 或虚构 blockId。创建的引用、同批操作顺序、可用 operation 类型按本次协议处理。
4. 已有富文本局部样式用合同允许的 Delta；段落样式用 update-block-props。createParameters 不接受的样式不要硬塞；若当前协议又不允许同批更新新引用，先创建可支持的结构，回读实际 ID 后再按允许的下一步更新。
5. 预检/预览、确认、修订与保存遵循宿主已有流程。工具返回 pending 不代表已执行；不新增一套审批系统，也不绕开现有流程。文本和属性修改可能有不同的修订展示能力，不能都称为可视 Diff。

当前若没有定位/组合的语义工具，不能用移动到不存在的 placement 容器或修改 DOM 模拟。若 API 未开放分页字段、placeholder 元数据或对象效果，也不能从完整编辑器文档偷渡到通用写入操作。完成独立可做部分，明确剩余效果需要哪类入口。

图片参考可用于理解语义；若宿主禁止视觉布局重建，本技能也不启用该功能。没有视觉工具时可以做基于文档模型的排版建议，但不声称像素还原或截图验证。

## 外部 AI / 原生编辑路径

优先使用已提供的文档工具或真实 UI。集成代码仅使用公开的 DocChain/DocCRUD/placement API，在事务里做结构和属性变更；不要直接改运行时 props、Y.Text 或 DOM。离线 Snapshot 也先用已安装 Schema 生成最小样例，再扩展；不要照搬别人文档的 ID 或用户素材 URL。

现有技能无需更改内核就能做的排版不要引入框架补丁。宿主上传服务返回的持久地址才是资产；不把临时本地路径或猜测的远端链接写成资源。

## 按布局验证

| 场景 | 实际检查 |
| --- | --- |
| 文档流 | 窄、中、宽三档及拖动过程；标题换行、分栏横向溢出、装饰线收缩 |
| 可增长正文 | 中间一段加入长文；后文下移，内容不被裁切；恢复测试内容 |
| 可删减栏目 | 删除中间区域后阅读顺序、编号和留白合理；恢复测试内容 |
| 文本框/组合 | 点击标题和正文能输入；检查行高、底部空白、旋转/缩放后的文字与图案 |
| 固定分页 | 第一页及溢出页、页边距、装饰层、页脚和页码；背景与边界不侵入正文 |
| 保存/导出 | 保存结束后回读；导出或打印只有任务需要时验，不能用编辑画布截图代替 |

测试修改优先在草稿/副本中进行，或使用可验证的撤销恢复，不留下虚构测试正文。以用户最后调整的数据为准；旧 HTML、生成脚本和模板配方不能覆盖新决定。

交付说明实际改动和验证范围。模型/合同验证、浏览器检查、真实桌面检查、保存持久化是不同证据；“设计建议合理”不能写成全部验证通过。
