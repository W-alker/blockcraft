# 文字与段落：把视觉层次放到正确的层级

> Last updated: 2026-10-08

## 四层职责

| 层级 | 负责 | 常见字段线索（以当前合同为准） |
| --- | --- | --- |
| 文档默认 | 正文基准字体、字号、颜色 | root 的 ff/fs/color/lh |
| 段落 | 语义标题、整段字号倍率、行距、段前后、对齐、装饰 | heading/pfs/lh/psb/psa/textAlign/decoration |
| 行内富文本 | 一个词/短语的粗体、颜色、字体、链接及原生材料 | Delta attributes，例如 a:bold、s:color、t:ff |
| 对象文字框 | 框内文字布局、内边距、基准效果 | textPadding/textAlignment/textFont/textSpacing/textFill |

`heading` 是 paragraph 的属性，不是独立 flavour。`pfs` 是段落字号倍率，不是 px。修改字体先看已有父级和行内覆盖，防止改了段落而部分文字仍保留旧样式。继承适合正文一致性；局部强调只改对应文字。不要同时在四层重复写同样样式。

## 可调整的视觉起点

通常正文 1×，栏目标题约 1.15–1.4×，主标题约 1.8–2.6×，注释约 0.85–0.95×；这是试排起点，不是强制比例。中文正文先试舒适行距，再按内容密度调整。正文中英混排和大标题要检查实际字体可用性、字面高度与换行，不能只看数值。

长文少用大面积居中；左对齐易读，justify 两端对齐用于长段落时检查词间距，distributed 会分散末行，不适合普通短标题。选择等宽字体应有代码/表格数据理由，衬线和无衬线可建立风格，不要每个栏目换一种。

留白有不同责任：psb/psa 分隔段落，lh 控制同段行距，容器 padding 控制文字到表面边缘，固定对象 height 控制画布占位。普通文章合理段间距有用；不要把为“未来填写”预留的大片空白写成提示段落段后间距。

## 标题与线条

- 右侧延伸横线：可编辑标题段落 + `decoration.position: 'after'`。
- 双侧短线：`both`；上下线：`above/below`。线条宽度、gap、opacity 和颜色服从标题层级。
- 区域之间的线：独立 divider；只有表面本身需要边界时才加容器边框。
- 段落 decoration 是边缘装饰，不是每一行的笔记横格，也不是文字下划线。下划线应使用现有行内格式；笔记纸效果另选当前已支持的表面/文本框样式。

原生示例片段（不是可直接提交的 Agent operation）：
```json
{"heading":2,"decoration":{"position":"after","style":"solid","color":"#B8C5B6","width":1,"gap":12}}
```
Agent 创建参数和已有块 writableProps 可能不同；不能把更新字段直接塞进 createParameters。窄宽优先让文字正常换行、装饰线缩短，不固定长线撑出页面。

## 填写说明和动态材料

模板提示使用宿主支持的 placeholder，保留真正正文为空；通常 `meta.plh` / `plhMode` 属于快照元数据。它们未开放给当前 Agent 时，不编造 `update-block-meta`，也不用普通正文冒充提示。

填写正文继承正常字号。提示视觉较弱应通过提示自身样式实现；不要因为提示字长给整个填写段落设 0.85×，否则用户输入也变小。检查 text-box 父级字号，而非只删除段落 pfs。

一行日期、作者、天气优先原生行内材料；需要视觉卡片才用块。复用已有格式和来源，不私造相似 embed。可选来源来自宿主配置，冻结在建档还是随打开更新由任务与合同决定，不能一律写死“创建人/今天”。`d:cfgSource`、业务莲花、字段名等不是跨宿主通用能力。

保护 Delta：文字按 UTF-16 偏移计数，行内对象占一个模型单位；美化不能把富文本转成 plain 后回写，导致日期、人员、链接丢失。只读/理解型 embed 不能靠猜序列化数据新建。
