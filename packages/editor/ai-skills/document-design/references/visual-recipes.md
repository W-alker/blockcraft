# 视觉制作流程与配方：先设计，再映射，再对照

> Last updated: 2026-10-08

## 何时先做 HTML

整体视觉任务默认先制作 HTML 样稿，让阅读顺序、构图、字体层次与留白在一次预览中可判断。HTML 不是最终文档，也不是自动导入即可保真的中间格式。只改文字或局部样式时直接编辑；已经有合适样稿时从能力核对和映射继续。

### 1. 用真实内容建立艺术方向

先读取要排版的实际内容。新文档先写出主要正文，再试排；不要用两行短占位设计出漂亮小卡，最后才塞入长文章。已有文档的事实、链接、行内材料、栏目和具名语义保留，设计不改变写作授权。

先明确阅读场景、交付尺寸、内容增长和用户希望的视觉气质。开局只核对会使整套方向无效的硬约束，不逐个点击工具栏探测所有字段后才开始设计。

为方向写出具体视觉命题：例如“有呼吸感的文学刊物”“繁复而清晰的植物藏书”“大胆的色块拼贴”。说明主视觉、标题字形、正文组织和空间节奏，不以“高级/华丽/简约”三个形容词代替设计。当风格仍不确定或用户否定现稿时，先探索两种有显著构图差异的开篇缩略稿，再选更合适的一种扩展完整正文；不是每次都强制多方案。

先解决构图而非列组件：可以使用不等宽列、侧注、抽取原文的引文、独立装饰、错位和层叠。长文可以在连续正文中插入视觉停顿，不必每一节都是同样的“序号 + 线 + 标题 + 一段字”。保留真实内容，不靠删字、假占位或大幅缩小正文获得漂亮轮廓。

不要把“已经会点击的控件”当成创意清单。编辑器能力、当前 Agent 写入能力、消费包版本和本次自动化工具的操作便利性是不同层面，设计方向形成后再分别核对。

### 2. 建立一份小型设计参数表

参数表是本次制作的共同依据，服务于 HTML 和原生数据；不是新增的 BlockCraft 存储格式。可以作为 HTML 内的一个数据对象，或同目录的 JSON，避免两端各维护一组数字。局部变更只记录涉及区域，不引入庞大的设计系统。

至少记录：页面/正文宽度与边距、色彩角色、目标字体和替代字体、正文基准字号、标题级别、行距、段距、内边距，以及每个区域的内容、视觉角色、顺序/位置和素材。探索阶段允许原生承载方式待定；落地阶段再补 carrier 与字段映射。注明单位、继承关系与验证状态，不能为了填满数据结构过早锁定构图。

例如以下是设计意图片段，不能直接提交为 Snapshot 或 Agent operation：
```json
{
  "layout": "flow",
  "tokens": {"bodyPx": 16, "sectionPx": 22, "bodyLineHeight": 1.7, "accent": "#48644D"},
  "regions": [
    {"key": "reflection-title", "carrier": "paragraph", "role": "section-heading", "decoration": "after"},
    {"key": "reflection-body", "carrier": "paragraph", "contentRef": "reflectionText"}
  ]
}
```

### 3. 先展示视觉探索，再补能力标注

- **纯预览**：只显示文档效果，使用真实文字与可获得的字体、素材，判断整体美感。
- **能力标注**：方向形成后，在文档外侧标出区域 key、候选原生承载方式、布局关系和待验证项。标注用独立覆盖层/侧栏，不占正文位置，不进入最终数据。

纯预览为默认视图，技术标注不能主导审美。固定纸张按目标纸张试排；用户明确要求可调宽时检查不同宽度。HTML 可用 CSS grid、定位、裁切、渐变或层叠来表达设计意图，不要求 CSS 写法和块结构逐行对应。

探索稿的响应式折栏、滤镜等未经验证的行为必须标为设计意图，不能声称原生支持；落地版要与实际行为一致。未要求网页交互时，不靠滚动动画、吸顶或悬停效果代替静态文档本身的美感。任何阶段都不靠裁切正文或自动缩小正文掩盖溢出。

图片只承载适合图像的装饰，不把文字/整页截图作为复刻结果。能用 shape 的几何图案保留为形状意图。背景纹理和可独立移动的装饰分开准备，真实上传与素材持久化遵守宿主流程。

### 4. 预览自检后收敛

在可用浏览器/预览器里看实际渲染，而非仅检查 HTML 源码。先检查第一眼能否形成清晰的视觉焦点，标题、正文和图像有没有共同的设计语言，开篇、中段、结尾是否有节奏。再检查可读性、对齐、空间和细节。

做一次“拿掉封面图”的检查：正文是否仍有辨识度？若剩下的只是统一字号、重复标题线和长段落列表，说明装饰尚未进入整体构图。可调整标题字形与比例、段落宽度、引文位置、侧栏、图文关系或章节表面，不是强迫每篇都有这些元素。流式段落承载文字，与整体视觉丰富并不矛盾。

高级感可以是克制的，也可以是丰盛的。用户要华丽时，允许精细边饰、图案、材质、饱和配色和更强的尺度对比，只要层次清晰、内容可读。不要把“少量装饰、一个强调色、全部左对齐”当作审美合格条件。现稿被否定时改变至少一个主要设计轴，不只调颜色与边距。

至少检查标题换行、主要正文长度、图文对齐、文本框底部空白、页脚边界。流式增加改宽和长文测试，固定布局检查后续页和删区后构图。没有原生自动重排能力时，不在 HTML 中制造删除后自动补位的承诺。

用户要求先看方案时展示并等待其后续要求；用户已授权制作全文时，自检后继续，不以这一步作为强制审批。用户有新调整，以其最新版本更新参数表和样稿。

### 5. 审查能力并制作原生落地版

此时读取相关 Schema/工具合同，给每个重要效果分类：原生直接实现；通过多个原生块或独立装饰素材等效实现；编辑器支持但当前 Agent/版本/操作入口受限；编辑器本身缺少能力。后二者不是同一种问题，也不构成绕过接口的许可。

保留探索稿，另记录落地差异。优先寻找保持设计意图的等效做法，而不是遇到缺口就删掉最有辨识度的设计；几何可以拆成形状/对象，复杂非文字装饰可以独立成图，真实标题和正文继续可编辑。若核心视觉确实无法实现，明确展示差异与选项，涉及扩展底层时再讨论具体方案；不能悄悄退回普通文章后声称还原完成。

建立按区域 key 对照的映射，不从截图反推坐标，也不遍历任意 DOM 猜块类型：

| HTML/设计意图 | 原生承载 | 映射重点 |
| --- | --- | --- |
| 标题、正文及强调词 | paragraph + Delta | heading、字号继承、行距/段距、局部 attributes；保留已有 embed |
| 并排阅读区域 | columns/column | 原生列关系、列宽与父子限制，不假设 CSS grid 可直接复制 |
| 独立便笺 | text-box + 子段落 | 布局宽高、文字安全区、textPadding；标题不再单独套框 |
| 共同移动的装饰组件 | object-group + 合法成员 | 当前入口是否支持创建/组合，成员相对位置，保持正文独立 |
| 页边图、纸纹、几何图案 | image、root 背景、shape | 独立职责、实际素材地址、形状目录和当前可写字段 |
| 标题旁线 / 模块分隔线 | paragraph decoration / divider | 前者跟随文字，后者独立占位，不让填写区边框替代所有线条 |

CSS 字号 px 与 pfs 倍率不能直接互抄。例如正文基准 16px、设计标题 24px，在确认继承基准确实为 16px 时才映射为 pfs 1.5。对象文字样式、行内覆盖可能改变结果，必须回看实际继承。CSS padding、行高、段距、对象 height 各有职责，不能都换成段后间距。

固定对象保存布局坐标，转换时计入正文原点与页边距；预览缩放不改变模型尺寸。颜色、尺寸和素材尽量从共同参数表读取，原生字段按当前 Schema 编码。HTML import 只有在对应 Adapter 已验证保留这些语义时才适用；不能用一次通用 HTML 导入替代原生映射。

原生 Agent 使用合法操作和 Schema 参数，不能交付原始 Snapshot 绕过协议。完整编辑器入口支持但当前 Agent 未开放的填充/阴影/组合等，不得编造写操作；改用已授权可用入口，或收敛到可实现版本并更新样稿。不能只交付 HTML 然后声称文档已经完成。

### 6. 在真实文档中对照修正

先实现一个代表性区域，比较实际字号、换行、文本框高度、样式继承与可编辑性，再推广。对照时使用相同内容、近似相同显示比例和视口；编辑器外壳及标注不计入文档构图。

先修原生结构、占位和断页，再修字号/行距/边距，最后调色彩/装饰。记录必要差异及原因；不为了像素一致去裁掉正文、缩小填写字体、将可编辑文字转图片或打内核补丁。因原生约束改变方案时同步参数表与样稿，避免继续对照过期 HTML。

检查可编辑、改宽/长文/删区行为，保存后回读。最终交付是原生文档及实际验证说明，HTML 留作可复用的设计依据。只有看到真实渲染才能声称视觉验证；数据字段一致、HTML 好看，都不等于原生文档已验证。编辑器内图片布局重建限制仍有效：本流程的参数映射不启用从任意图片还原布局的权限。

## 从阅读重点决定装饰

先确定标题、正文、辅助信息的阅读顺序，再安排主色、表面色、正文色与强调色的角色和面积。强调色数量、装饰密度和对比强度服从选定风格，不预设只能有一种。协调来自统一的设计语言，不只是减少效果数量。

用一组间距尺度形成节奏，例如 4/8/16/24/32；按字体与纸张调整，不把这组数字当作 Schema 默认。卡片对齐文字边缘和视觉重心，别只按外框对齐。颜色须在实际底纹上检查，浅色正文不能因“复古”而难读。

## 背景、图形和效果分工

- 纸色、渐变、重复纹理可作为文档背景。不要把正文、日期、可编辑标题或独立徽章烘焙进背景。
- 花束、邮票等独立图片可以移动、替换或删除；几何丝带/气泡优先原生 shape，装饰性短字可用 word-art。目录已有相同图形就不再画成图片。
- 页脚属于分页配置；需要两种视图都读到的结语放正文末尾。模板封面缩略图、文档头图、纸张背景是不同数据。
- 效果强度服从视觉方向：纸张叠层可用柔和投影，舞台/拼贴可有明确硬影或发光。颜色、光向和层级要一致，不能不分主次地给每个区域叠同样效果。

完整编辑器的对象格式采用紧凑字段，例如 fill、outline、shadow、glow、textPadding；不要保存运行时的 shapeFill/textFrame/effects 大对象。Agent 是否能写这些字段由当前 writableProps 决定。发现只开放几何时，先完成位置/正文整理，样式留给已授权的原生 UI 或说明限制，不绕过能力校验。

## 四种组合示例

这些是设计决策示例，不是可直接插入的固定模板。主题和栏目用用户自己的内容替换。

### 工作简报：窄宽、长内容

主标题 paragraph → 日期/作者行 → 栏目 heading + 正文/列表 → divider。强调一项结论时才用 callout。整体以对齐、字重和间距建立层次，避免所有栏目套固定文本框；删除一节后后文自然上移。

### 暖纸手记：可调宽的装饰文档

暖白背景 → 衬线标题段落 → 行内日期/天气 → 标题与正文纵排，标题可加 after 线。植物图可独立保留，但不能覆盖主要书写区域。固定花牌仅在有足够稳定空间并验证窄宽后加入，不因植物风格默认强制分页。

### 花笺：固定纸张中的文档流

柔和底纹 → 独立角花图片 → 流式居中标题；丝带用 shape。日期与人员可用分栏/行内材料，不外套无用内容容器。正文保持可增长段落；页边邮票独立图片。标题与花饰不必同组。检验长文翻页时页边图与页脚是否干扰正文。

### 拼贴：对象主导的固定构图

纸纹背景 + 独立太阳/贴纸图 → 少量艺术字标题 → 便笺文本框，框内标题和正文都是段落。同一区域不拆成“编号框 + 标题框 + 正文框”才可编辑。确需共同移动的图文再组合。可用通栏主卡 + 下方双卡，而不固守四等份。

删除一张便笺后的留白可以成为构图，但这不等于自动重排；用户要求删区后紧凑时改用分栏或纵向文档流。正文超长时调整结构/增加页，不把正常字号缩小到看不清。

## HTML 示意边界

用户要求示意时，标出原生承载方式与尚未开放的操作。预览里的 CSS grid、响应式断点、滤镜、吸顶不能自动视为编辑器能力。正文保留实际可选中可编辑的文字，独立素材单独列出，避免制作完成后才发现整个页头是一张图。仅有图片参考时，遵守当前 Agent 对图片的限制，不从本技能推导出图片布局重建权限。
