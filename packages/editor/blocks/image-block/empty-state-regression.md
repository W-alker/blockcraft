# 空图片紧凑占位回归

## 规则与影响范围

未设置资源的流式图片（包括分栏、表格等正文容器内的图片）使用上传提示的自然高度，默认至少 80px；不再被已存的 `wr/ar` 或默认比例撑高。编辑器和 Snapshot Viewer 共用图片主题中的上传提示样式。

只投影视图状态，不修改图片保存的数据，也不增加尺寸测量或 ResizeObserver。加载、失败、协作上传中的图片都有资源标识，继续保留图片框比例。浮动和组合成员由 `data-bc-placement="absolute"` 排除，保留既有定位渲染路径；静态预览中这类空图不套用本次新上传提示布局。插入照片仍经过原来的尺寸初始化、宽度约束和上传流程。

## 浏览器复现

1. 在文档及 Snapshot Viewer 中分别放入 `src: ''`、`wr: 100`、`ar: 1.65` 的图片，嵌入 42/58 分栏。
2. 检查 `.img-wrapper` 与 `.upload-hint` 的布局高度相同，不在上传提示下方留出图片比例产生的空白。
3. 同一图片写入资源后，空图标记移除，按图片比例恢复；清空资源后重新收紧。
4. 在 `placement-layout` 与 `object-group` 中检查同样的空图片，确认原有比例和坐标保留。
5. 检查资源加载失败、只读预览及图注；它们不得通过隐藏 overflow 或修改保存尺寸实现。

真实账号上传、服务端保存重开和 Tauri 桌面验收不由隔离浏览器夹具替代。

## 验证边界

浏览器验证使用隔离的 BlockCraft 源码副本。整仓入口存在与本修复无关的严格类型错误：`fixed-toolbar.component.ts` 的三个索引属性访问，以及并行改动中的 `material-renderers.ts` 可空 `ref`。仅在临时副本中改成方括号访问和非空断言以生成验证页，运行时逻辑不变；没有修改这些仓库源码或放宽测试断言。此结果不能视为整仓生产构建通过。

CSES 客户端当前安装的包未替换；本修复随 BlockCraft 包更新后进入客户端。工作区现有的 `0.11.6` 版本变更与本修复一并提交，尚未发布。

浏览器实测（隔离源码夹具）：42/58 分栏中的编辑器空图宽约 259px、预览空图宽 270px，图片框与上传提示均高 80px。写入 2:1 的本地内存图片样本后，编辑器为约 259×129.5px，预览为 270×135px；清空后均恢复 80px，控制台无错误。此操作验证资源状态切换，不代表真实文件上传链路。浮动/组合空图被排除出 80px 收缩规则，但该夹具中其百分比宽度仍出现窄列显示，未据此宣称浮动几何验收通过；相关模型比例和坐标保留由定向测试覆盖。
